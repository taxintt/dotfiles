# Grill Me Skill

実装前に、ユーザーを **relentless にインタビュー**して plan / 設計の理解を
共有レベルまで結晶化する。**成果物（設計書 / plan / PRD）はこの skill では作らない** —
理解が揃ったら次の skill へ handoff する。

## 発火タイミング
- plan / 設計 / 生アイデアを作る前に stress-test したい
- 要件を「詰めたい」
- ユーザーが「詰めて」「grill して」と言った、または `/grill-me` と呼んだとき

## 進め方
design tree を branch ごとに歩き、決定間の依存を 1 つずつ解決しながら、
共有理解に達するまで relentless に質問する。

- **質問は必ず 1 問ずつ**。回答を待ってから次へ。複数同時投下は混乱を招く。
- **各質問に推奨回答を添える**（「私なら X。理由は…」）。
- **コードベースで答えられる問いは、ユーザーに聞かずコードを探索して自分で答える**。
- 推測で進めない。曖昧な回答は具体的選択肢を示して押し返す。

## 終了条件と handoff
共有理解に達したら:
1. 確定した理解 / 未確定の論点を簡潔に要約する。
2. 次に呼ぶべき skill を推奨する（**この skill では成果物を書かない**）:
   - 設計書 → `design-interview`
   - 実装計画 → `implementation-planning`
   - ドキュメント計画 → `doc-planning`

## Red Flags — STOP
- 質問を一度に複数投げている（番号付きリストや小問の束も「複数」とみなす）
- 1 メッセージで「まとめて答えてください」と回答を促している
- 推奨回答を省いている
- コードを見れば分かる事をユーザーに質問している
- 「だいたい分かったから実装に進む」と理解共有を飛ばしている

これらが出たら STOP し、**今その瞬間に最も重要な 1 問だけ**に絞り直す。

## 関連
- 設計書化: `design-interview` / 実装計画: `implementation-planning`
- 既存 plan の深掘り強化: `dig`（plugin）
- 連鎖: `idea-to-pr-chain` skill（アイデア → PR 一気通貫）
