# Handover Skill

現在のセッションの作業状態を `HANDOVER-YYMMDDTHHmm.md` として記録し、次のセッションがすぐに作業を再開できる状態にする。

## 発火タイミング

- セッションを終了する前に作業状態を引き継ぎたい
- ユーザーが「引き継ぎ」「handover」と依頼
- `/handover` として明示呼び出し

## 手順

### ステップ 1: 現状把握 (並列実行)

- `git status` — 未コミット変更の確認
- `git log --oneline -10` — 直近のコミット履歴
- `git diff --stat HEAD` — 変更サマリー
- カレントディレクトリの PROGRESS.md / TODO.md / NEXT.md の有無確認

### ステップ 2: セッション内容の整理

会話の文脈から以下を抽出:

1. **作業目的** — このセッションで達成しようとしていたこと
2. **完了済みタスク** — 実際に完了した作業
3. **未完了タスク** — 途中で止まっている作業
4. **次のアクション** — 次のセッションで最初にやるべきこと (具体的に)
5. **重要な決定事項** — 採用した設計・方針と理由
6. **ブロッカー** — 判明している障害・未解決の疑問

### ステップ 3: ファイル名の決定

現在時刻から `HANDOVER-YYMMDD-HHmm.md` を決定する。
`date +%y%m%d-%H%M` コマンドで取得する。

### ステップ 4: ドキュメント生成

以下の構造でファイルを生成する:

```markdown
# Handover: YYYY-MM-DD HH:mm

## 作業目的

[このセッションで達成しようとしていたこと]

## 完了済みタスク

- [x] タスク名 — 簡潔な説明
- [x] ...

## 未完了タスク

- [ ] タスク名 — 現在の状態と残作業
- [ ] ...

## 次のアクション

1. [最初にやること] — [なぜこれが最初か]
2. [次にやること]
3. ...

## 重要な決定事項

| 決定内容 | 理由 |
|---|---|
| [採用した方針] | [なぜこれを選んだか] |

## ブロッカー / 未解決事項

- [障害・疑問] — [現状の仮説や試したこと]

## 関連ファイル

- `path/to/file` — [役割]

## Git 状態

[git status / git log の要約]
```

### ステップ 5: 生成前の確認

ファイルパスと内容サマリーを提示してユーザーに確認を求める。承認後に書き込む。

## Iron Law

- **推測禁止**: 会話に存在しない情報は「不明」と記載する
- **ファイル書き込みは確認後のみ**: 承認なしに HANDOVER ファイルを作成しない
- **既存ファイルの上書き禁止**: 同名ファイルが存在する場合は別名を提案する
- **ドキュメント本体の作業はしない**: 引き継ぎ書を作るだけ。実装・修正は行わない
